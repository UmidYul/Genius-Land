## 2. Этапы (с учётом зависимостей)
| Этап | Срок (ориентир, 1–2 разработчика) | Содержание | Результат |
|---|---|---|---|
| 0. Подготовка | 1 нед. | Выгрузка данных из старой системы (Q-18), уточнения K, дизайн БД, CI, Docker | Схема БД, репозиторий, тестовые данные |
| 1. Ядро | 3 нед. | F-01…F-05, F-26 | Вход, роли, реестры, импорт |
| 2. Деньги | 3–4 нед. | F-09, F-10, F-11 (+ интеграция долгов с CRM колл-центра) | Бухгалтерия работает в новой системе |
| 3. Учебный день | 3 нед. | F-06, F-07, F-08, F-13, F-15 | Учителя ведут журнал |
| 4. Родители | 3 нед. | F-12 (web, затем mobile), F-21 (уведомления) | Родитель видит баланс и оценки |
| 5. HR | 2–3 нед. | F-17 | Кадры и зарплата |
| 6. Конец периода | 2 нед. | F-16, F-25 | Табели, перевод, отчёты |
| 7. Договоры и приём | 3–4 нед. | F-18, F-19, F-20 | Электронные договоры, набор |

Тестирование на каждом этапе: автотесты сценариев F, затем UAT с бухгалтером, учителем и родителем; переход модуль за модулем (параллельная работа старой и новой системы на время сверки).

## 3. Главные риски
1. **Данные:** без полной выгрузки придётся переносить вручную. Сделать выгрузку (Q-18) немедленно.
2. **Финансовые формулы:** ошибки бьют по доверию родителей. Нужны письменные политики (пропорции, удержания, округление, аванс) от бухгалтерии до начала этапа 2.
3. **Объём:** старая система очень широкая (~1 000 операций API). Не пытаться повторить всё — делать P0/P1, остальное по запросу.
4. **Юридическая значимость электронной подписи:** уточнить у юриста до реализации F-18.

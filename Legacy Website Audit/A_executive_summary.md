# Документ A. Executive Summary

**Объект:** Genius Land — «Maktab Boshqaruv Tizimi», веб-платформа частной общеобразовательной школы (Маргилан, 1–11 классы). Адрес: geniusland.uz. Аудит проведён 23.10.2026 под учётной записью SUPER_ADMIN.

## Что это за система
Очень широкая школьная ERP + CRM (версия 2.0.0): React SPA + REST API (`/api/v1`, ≈ 1 000 операций), PostgreSQL, realtime через socket.io, SMS через Eskiz, мобильное приложение для родителей и учеников (по косвенным признакам). **37 ролей**, **226 прав** с областями видимости (своё, свой класс, свой предмет, школа).

## Основные модули (46 найдено, см. B)
Учебный процесс (расписание, журнал, посещаемость, оценки, ДЗ, тесты, итоговые оценки и табели, перевод и выпуск) · Люди (ученики, родители, учителя, сотрудники, пользователи) · Дисциплина (нравственные баллы, устав) · Геймификация (монеты, магазин, семейные миссии) · Финансы (тарифы, скидки, счета, платежи, лицевые счета-леджер, касса, банк, сверка, расходы, бюджет, автогенерация) · Договоры с родителями (DOCX-шаблоны, кампании, электронная подпись OTP/на месте, доп. соглашения, взыскание долгов, закрытие года) · Приём (CRM: лиды, скоринг, воронка, заявки, вступительные экзамены, очередь, публичная анкета) · HR (отделы, штатное расписание, трудовые договоры, табель, отпуска, аттестация, зарплата) · Транспорт · Библиотека · Столовая · Коммуникации (уведомления, SMS, чат, объявления, новости, сторис, события) · Отчёты (23 в каталоге + 20 по договорам) · Аудит и система.

## Что реально используется в проде (по данным)
629 учеников, 69 учителей, 37 классов, 20 предметов, 393 урока в расписании, ~1 244 пользователя, посещаемость (частично), дисциплина (9 записей), 1 тест, 2 ДЗ. **Пусто:** финансы (0 платежей), договоры, приём, HR, транспорт, библиотека, столовая. Онлайн-оплаты выключены. Четверти не созданы.

## Полнота аудита
- **Инвентаризация:** полная (92 маршрута, 46 модулей, каталог API, матрица прав) — уровень «Подтверждено».
- **Формы:** снято 38 форм создания (поля, обязательность, умолчания, диапазоны).
- **Бизнес-правила:** 126 правил, из них ~55 подтверждены экспериментом или ответом сервера, остальные — частично (конфигурация или тексты UI).
- **Тесты:** 54 эксперимента на тестовых данных (E03). Создано 3 класса, 3 ученика, 2 тарифа, 2 скидки, 3 счёта, 2 платежа, 7 оценок и др. — все с меткой TESTAUDIT; их нужно удалить вручную.
- **Не покрыто:** работа под другими ролями (нужны тестовые учётки, вход делает владелец), договоры, приём, HR и зарплата, итоговые оценки — сценарии и вопросы вынесены в F и K.

## Главные выводы и риски
1. **Финансовая логика старой системы ошибочна** (H ISS-01…05): переплата принимается сверх счёта, аванс не зачитывается, ученик одновременно и должник, и кредитор, скидка 150 % и отрицательный тариф проходят. В новой системе финансы строим на леджере с распределением платежей — это главное отличие.
2. **Данные прода с изъянами:** 21 конфликт учителей в расписании, нет четвертей, посещаемость отмечается примерно у 13 % учеников, номера-заглушки у родителей после импорта.
3. **Критичное неизвестное** — полная выгрузка данных. Сделать её сейчас, пока есть доступ (кнопка экспорта в «Tizim salomatligi», экспорты реестров).
4. Объём старой системы велик; повторять всё не нужно — план (J) начинается с P0/P1: ядро, деньги, учебный день, родители, HR.

## Рекомендуемая стратегия
Модульный монолит Node.js (NestJS) + PostgreSQL + Prisma, React web, React Native mobile, BullMQ для фоновых задач. Каждый модуль внедряется с параллельной сверкой со старой системой. Срок ориентировочно 5–6 месяцев на P0–P2 силами 1–2 разработчиков; MVP (ядро + финансы + журнал) — 2–2,5 месяца.

# Документ K. Неизвестные и вопросы для уточнения

| ID | Вопрос | Значимость | Как проверить |
|---|---|---|---|
| Q-01 | Как реально работают роли, кроме SUPER_ADMIN (меню, область видимости CLASS / OWN, ограничения на запись) | Высокая — от этого зависят порталы учителя, родителя и ученика | Создать тестовые учётки TEACHER, PARENT, STUDENT, ACCOUNTANT, CASHIER, REGISTRAR; владелец сам входит под ними, далее TC-160…169 |
| Q-02 | Формула и округление четвертной и годовой оценки; поведение NOT_ENOUGH | Высокая | Создать четверти у тестового года, поставить оценки тестовому ученику, выполнить bulk-calculate |
| Q-03 | Как создаются четверти (UI не найден) и что делает «quarterId» у оценки | Высокая | Спросить у пользователей школы; проверить вкладку «Akademik → O'quv yillari» |
| Q-04 | Какая формула удержания за болезнь применяется: месяц / 22 или фикс 35 000 | Высокая (деньги) | Тестовое разрешение на отсутствие → apply deductions → проверить следующий счёт |
| Q-05 | Политика пропорции при зачислении в середине месяца | Средняя | Решение бухгалтерии школы |
| Q-06 | Распределение платежа на несколько открытых счетов (быстрая оплата `quick-payment`, `payments/class/:id/bulk`) | Высокая | Тест на тестовом ученике с 2 счетами |
| Q-07 | Совмещение скидок (canCombine, priority, min/max) | Средняя | Две скидки одному тестовому ученику |
| Q-08 | Расчёт зарплаты: состав (оклад × ставка, надбавки, удержания, налоги, ИНПС), влияние табеля | Высокая для HR | Тестовый сотрудник → generate payroll → breakdown |
| Q-09 | Нормы отпусков, перенос, правило «24 дня» по категориям (педагогам по закону больше) | Средняя | HR школы |
| Q-10 | Автоматические меры по порогам нравственных баллов (уведомления, задачи) | Средняя | Тестовый ученик довести до 70 / 50 |
| Q-11 | Шаблон договора (текст, пункты 3.4, 3.6.1, 4.3, 5.2) и правовые формулировки | Высокая | Запросить у школы действующий DOCX-договор |
| Q-12 | Подпись: ERI (ЭЦП), интеграция OTP по SMS, хранение доказательств (фото, IP, время) | Высокая | Документация провайдера, тестовый договор с номером владельца |
| Q-13 | Мобильное приложение: функции, push (FCM?), версия API | Высокая | Получить APK/IPA или ссылку на магазин; проверить, что приложение работает с тем же API |
| Q-14 | Интеграции: ESKIZ (ключи), Payme / Click / Uzum (merchant ID), банк | Высокая | Владелец — договоры с провайдерами; ключи выпускаются заново на новую систему |
| Q-15 | Какие разделы реально используются школой (финансы, HR, приём, договоры сейчас пусты) | Высокая для приоритетов | Интервью с директором и бухгалтером; журнал активности |
| Q-16 | Импорт Excel: точный формат колонок для учеников, учителей и расписания | Средняя | Скачать шаблоны импорта из UI (кнопки Import / Excel import) |
| Q-17 | Монеты: дневной лимит, уровни (XP → level), магазин наград | Низкая | Вкладка «Nazorat» и «Do'kon» |
| Q-18 | Резервное копирование и экспорт данных (`/settings/backup`, «Ma'lumot eksporti» в system-health) | **Критическая** — это законный способ забрать свои данные из старой системы | Нажать «Eksportni yuklab olish» в /system-health (владелец), проверить полноту выгрузки |
| Q-19 | Мультишкольность и филиалы — нужно ли в новой системе | Средняя | Решение основателя |
| Q-20 | Округления денег (до сума, до 1000?) | Средняя | Тестовый счёт с 1/3 скидки |
| Q-21 | Уникальность названия класса — в пределах года или навсегда | Низкая | Создать класс с тем же именем в другом тестовом году |
| Q-22 | Поведение при удалении учителя или класса со связанными уроками и оценками | Средняя | Тест на тестовых записях |

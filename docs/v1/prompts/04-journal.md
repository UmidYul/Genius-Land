# Этап 4 — Журнал: посещаемость, оценки, темы, итоговые оценки

## Промт

Продолжаем платформу Genius Land. Прочитай `CLAUDE.md`, `PRODUCT.md` (Product Principles — «Fast entry»), `docs/v1/PLAN.md` (§3.5, §3.9), `docs/legacy-decisions.md` (правила 1–6, 15) и общие правила в `docs/v1/prompts/README.md` — следуй им.

Задача: электронный журнал. Главный экран — «Мой урок» на телефоне: учитель за секунды отмечает посещаемость, ставит оценки и записывает тему.

Работай в ветке `feature/v1-04-journal`.

**Перед началом спроси Umid** о двух открытых вопросах, если они ещё не закрыты в `docs/v1/PLAN.md` §6:
- Q3 — посещаемость по урокам или по дням (предложение: по урокам, дневной статус выводится);
- Q4 — шкала и формула итоговых оценок (предложение: 5-балльная 2–5, среднее с округлением 0,5 вверх, минимум 3 оценки, годовая = среднее четвертных).
Шкалу, минимум оценок и правило округления в любом случае сделай настройками.

Сделай:
1. **Урок** `Lesson`: создаётся из `getScheduleForDate` (этап 3) при первом открытии. Тема урока, кто провёл (учитель или замена).
2. **Экран «Мой урок»** (mobile-first, одной рукой):
   - открывается текущий или ближайший урок учителя по расписанию;
   - список учеников, по умолчанию все «присутствуют», отметки одним касанием: отсутствует, опоздал, уважительная, болеет;
   - оценки прямо в списке (быстрый выбор значения), тип оценки;
   - поле темы урока;
   - автосохранение, повторное сохранение не создаёт дубликатов;
   - работа при плохом интернете: изменения не теряются, сохраняются при восстановлении связи.
3. **Посещаемость** (правила 1–3): одна отметка на ученика за единицу учёта, повторная обновляет; нельзя в нерабочий день (`isSchoolDay` по типу класса) и в будущее; правка старше N дней (настройка, по умолчанию 7) — только с отдельным правом и причиной; аудит. Дневная сводка по классу и филиалу.
4. **Оценки** (правила 4–5): значение строго в пределах шкалы; правка и аннулирование — только с причиной, история «было/стало».
5. **Журнал класса по предмету**: таблица «ученики × даты» с оценками и пропусками, на телефоне — удобный вид. Учитель видит свои классы и предметы, классный руководитель — все предметы своего класса (только просмотр чужих предметов).
6. **Итоговые оценки** (правило 6): расчёт четвертной по формуле из настроек, учитель выставляет итог (может отличаться от расчётного — с причиной), статусы «черновик → утверждена → заблокирована». Утверждает и разблокирует директор. Утверждённая не пересчитывается. Годовая — по той же схеме.
7. **Контроль заполнения**: для администратора и директора — какие уроки за день или неделю без отметок и темы.
8. **Доменные события**: «отмечен пропуск/опоздание», «поставлена оценка», «итоговая утверждена» — для уведомлений в этапе 6.
9. **Основа дисциплины** (правило 15, только данные, без UI): таблицы `ViolationType`, `DisciplineRecord`, `MoralScoreEntry` (PLAN §3.9); подписчик на событие «пропуск/опоздание», выключенный настройкой `discipline.autoIncidents = false`. Тест, что при включённом флаге создаётся запись, при выключенном — нет.

Права: учитель — свои уроки; классный руководитель — просмотр всего своего класса; администратор — контроль и правка посещаемости в филиале; директор — просмотр, правка, утверждение итоговых; основатель — просмотр.

Тесты: правила 1–6; окно правки; суббота для групп 8–11 разрешена, для 1–7 — нет; повторное сохранение без дублей; область `ASSIGNED`/`HOMEROOM`; E2E «Мой урок» на 360 px.

Открой PR в `main`.

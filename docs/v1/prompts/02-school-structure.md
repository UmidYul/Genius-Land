# Этап 2 — Структура школы и люди

## Промт

Продолжаем платформу Genius Land. Прочитай `CLAUDE.md`, `PRODUCT.md` (раздел School), `docs/v1/PLAN.md` (§3.1, §3.3), `docs/legacy-decisions.md` и общие правила в `docs/v1/prompts/README.md` — следуй им.

Задача: учебный год, календарь, предметы, классы и группы 8–11, сотрудники, ученики и родители. Плюс импорт из Excel.

Работай в ветке `feature/v1-02-school-structure`.

Ключевая особенность школы — запомни:
- 1–7 классы — обычные классы (`Class.type = REGULAR`, `gradeLevel` 1–7, «5-А»).
- 8–11 классы учатся **только в группах по направлениям** («ЭКОНОМИКА 1», «МЕДИЦИНА 2»). Группа — полноценный класс (`Class.type = DIRECTION_GROUP`): свой классный руководитель, свой состав из учеников разных классов 8–11. Номер класса ученика 8–11 — только атрибут для отображения и отчётов.
- У каждого класса и группы есть классный руководитель.
- Учебная неделя: 1–7 — пн–пт; группы 8–11 — пн–сб (суббота до обеда).

Сделай:
1. **Учебный год и четверти**: год создаётся сразу с четвертями (даты редактируются), один текущий год на филиал.
2. **Рабочий календарь**: праздники и переносы (на филиал или на оба), правило рабочих дней по типу класса. Функция `isSchoolDay(class, date)` в `packages/core` — её будут использовать посещаемость, журнал и бот.
3. **Справочники**: предметы, направления (Экономика, Медицина, Филология… — список редактируемый).
4. **Классы**: создание, редактирование и архив; тип, название (уникально в пределах филиала и учебного года), направление (для групп), вместимость (задаётся явно, обязательна), классный руководитель. Список с заполненностью «занято / вместимость».
5. **Сотрудники**: ФИО, телефон, должность, филиал, связь с учётной записью. Назначения учителей `TeachingAssignment` (учитель × класс × предмет). Наполни области `ASSIGNED` и `HOMEROOM` из этапа 1 реальными данными и добавь тесты.
6. **Ученики**: номер `GL-` + 6 цифр (сквозной, правило 8), ФИО, дата рождения (не в будущем), пол, номер класса 1–11, филиал, класс/группа, контакт на экстренный случай. Проверки: нельзя превысить вместимость (правило 7); для `REGULAR` номер класса ученика совпадает с `gradeLevel`; для `DIRECTION_GROUP` — номер 8–11; предупреждение о возможном дубле (ФИО + дата рождения). Перевод между классами и смена статуса (активен, выбыл, выпущен, переведён) — с историей и аудитом. Карточка ученика: данные, родители, класс, история.
7. **Родители/опекуны**: ФИО, телефон (уникальный пользователь), связь «родитель ↔ ребёнок» (один родитель — несколько детей, у ребёнка — несколько родителей, главный контакт). При создании родителя создаётся учётная запись без пароля (родители не входят в веб; позже — приложение и бот). Наполни область `CHILDREN`.
8. **Импорт из Excel** (exceljs): ученики, родители, сотрудники, классы. Шаблоны для скачивания; предпросмотр с ошибками по строкам; импорт только валидных строк одной транзакцией; отчёт. Формат выгрузки старой системы неизвестен — сделай собственные шаблоны, сопоставление колонок старой выгрузки будет в этапе 8.
9. **Экспорт в Excel** из каждого реестра с учётом фильтров и прав.
10. Все реестры: поиск, фильтры, пагинация, работа на телефоне.

Права: директор и администратор — всё в своём филиале; учитель — просмотр учеников своих классов; бухгалтер — просмотр учеников назначенных филиалов; основатель — просмотр обоих.

Тесты: `isSchoolDay` для обоих типов классов и праздников; вместимость; номер класса для групп; изоляция филиалов; импорт с ошибочными строками.

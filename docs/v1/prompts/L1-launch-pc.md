# Этап L1 — Временный запуск на ПК-сервере школы

## Промт

Продолжаем платформу Genius Land. Прочитай `CLAUDE.md`, `PRODUCT.md`, `docs/v1/PLAN.md` (§2.2, §2.5 и раздел «Временный запуск на ПК»), `docs/LAUNCH-PC.md` и общие правила в `docs/v1/prompts/README.md` — следуй им.

Задача: подготовить всё, чтобы платформа на 1–2 недели заработала на ПК-сервере школы, пока не куплен VPS. Утром Umid должен поднять всё **за 30–40 минут** по инструкции. Потом тот же код и та же база переезжают на VPS без изменений для учителей.

Этот этап не зависит от этапов 3, 4 и 2b — его можно делать параллельно в отдельной сессии. Он меняет только инфраструктуру, вход и импорт.

Работай в ветке `feature/v1-L1-launch-pc`.

Решения Umid (24.10.2026):
- **Сервер — ПК в школе**, домен — отдельный домен Umid (не geniusland.uz), доступ из интернета через **Cloudflare Tunnel** (без белого IP и открытых портов).
- **Вход только по логину и паролю, без кода подтверждения.** Учителям уже выданы логины и пароли от старой платформы, у Umid есть их JSON. Пароли **не меняются**, новые не выдаются.

Сделай:

1. **Вход без кода — настройкой, не удалением кода.**
   - Новая глобальная настройка `auth.deviceCode.enabled` (по умолчанию `true`). При `false` код с нового устройства не запрашивается, устройство сразу считается доверенным. Сброс пароля по коду при `false` скрывается: пароль сбрасывает суперадмин.
   - Значение можно задать переменной окружения `AUTH_DEVICE_CODE_ENABLED=false` (она главнее значения в БД) — чтобы на ПК всё работало с первой минуты.
   - Аудит: в журнал входа пишется «вход без кода (выключено настройкой)».
   - Всё остальное остаётся: блокировка после неудачных попыток, rate-limit, сессии.
   - Тесты на оба режима.

2. **Импорт учётных записей из JSON старой платформы** — CLI-скрипт `pnpm import:legacy-users <путь к json> [--dry-run]`.
   - **Безопасность прежде всего**: файл с паролями никогда не попадает в git. Путь передаётся аргументом; добавь в `.gitignore` папку `import/` и `*.legacy.json`. Скрипт **никогда не печатает и не логирует пароли и хэши**, даже в режиме отладки. После импорта — подсказка удалить файл с диска.
   - **Сначала изучи структуру файла**, не выводя значения паролей: выведи список полей и типы, количество записей, примеры без паролей. Определи, в каком виде пароль:
     - открытый текст → хэшируем argon2id при импорте;
     - хэш bcrypt (`$2a$`/`$2b$`/`$2y$`) → сохраняем как есть с пометкой алгоритма; при входе проверяем bcrypt, а после успешного входа **молча перехэшируем в argon2id** (пользователь ничего не замечает);
     - другой формат → остановись и спроси Umid.
   - **Логин.** Сейчас вход по телефону. Если в старой платформе логин — не телефон (например, GL ID или e-mail), спроси Umid и добавь вход по этому идентификатору (уникальное поле `login`, вход «телефон или логин»).
   - **Роли.** Покажи Umid таблицу «роль в старой системе → роль в новой» (SUPER_ADMIN, ADMIN, DIRECTOR, TEACHER, ACCOUNTANT и т. д. → основатель, директор, администратор, учитель, бухгалтер, суперадмин) и **дождись подтверждения** (это данные из legacy — правило 2 в `CLAUDE.md`). Ученики и родители из JSON импортируются только если Umid скажет.
   - **Филиал**: если в JSON его нет — спроси Umid, как распределить (например, отдельным списком или вручную после импорта).
   - Создаются `User` + назначение роли + связь с `Staff` по телефону (`linkStaffToUser`); сотрудник без записи `Staff` — создаётся. Флаг «сменить пароль при первом входе» **не ставится**.
   - Повторный запуск не создаёт дублей (сопоставление по телефону/логину), существующих пользователей не перезаписывает без флага `--update`.
   - Отчёт: создано, пропущено (с причиной), ошибки по строкам — без паролей.
   - Тесты на маленьком искусственном JSON (без реальных данных): открытый пароль, bcrypt-хэш с перехэшированием при входе, дубли, неизвестная роль.

3. **Продакшн-сборка**:
   - `Dockerfile` для web (Next.js `output: 'standalone'`) и для worker; многоэтапная сборка, финальный образ без dev-зависимостей, запуск не от root.
   - Миграции применяются автоматически при старте (отдельный одноразовый сервис `migrate` перед web и worker).
   - Сид для production: только права и роли (`syncAccessModel`), **без демо-пользователей**, и два филиала с названиями из PLAN §6 Q1. Первый суперадмин создаётся командой `pnpm create:superadmin` (телефон и пароль спрашиваются в терминале, не в аргументах).

4. **`docker-compose.prod.yml`** — один файл, всё в нём:
   - `postgres` (данные в именованном volume, без публикации порта наружу), `migrate`, `web`, `worker`, `cloudflared` (`cloudflare/cloudflared`, команда `tunnel run`, токен из `CLOUDFLARE_TUNNEL_TOKEN`), `backup`;
   - `restart: unless-stopped`, healthcheck у postgres и web, `depends_on` по готовности;
   - web не публикует порты наружу — только в сеть compose, туннель ходит к `http://web:3000`;
   - **`backup`**: каждый день в 21:00 по Ташкенту `pg_dump -Fc` в папку на диске ПК (`./backups`, путь — переменная), хранить 14 дней; плюс команда `pnpm backup:now` (или `docker compose ... run backup now`) для ручного бэкапа.
   - `.env.production.example` со всеми переменными и комментариями на русском: пароль БД, секреты сессий (подсказка, как сгенерировать), публичный URL, `CLOUDFLARE_TUNNEL_TOKEN`, `AUTH_DEVICE_CODE_ENABLED=false`, путь к бэкапам, путь к файлам (фото сотрудников из этапа 2b).

5. **Скрипты запуска** в `scripts/`:
   - `setup.ps1` (Windows) и `setup.sh` (Linux): проверяют, что Docker запущен; создают `.env.production` из примера и **сами генерируют** пароль БД и секреты; спрашивают только домен и токен туннеля; собирают и поднимают compose; ждут, пока web ответит; печатают адрес и следующий шаг (создать суперадмина, импортировать пользователей).
   - `update.ps1` / `update.sh`: бэкап → `git pull` → пересборка → перезапуск (миграции применятся сами).
   - `restore.ps1` / `restore.sh`: восстановление из выбранного файла бэкапа (с подтверждением).

6. **Переезд на VPS** — раздел в `docs/LAUNCH-PC.md`: бэкап на ПК → копия файла на VPS → `setup.sh` на VPS → `restore.sh` → в Cloudflare переключить туннель (или новый токен) и при желании домен на geniusland.uz. Учителя ничего не замечают, пароли те же.

7. **Проверка** перед PR: на чистой машине (или в CI-задаче) `docker compose -f docker-compose.prod.yml up` поднимается без ручных шагов, кроме `.env.production`; web отвечает; миграции применились; `backup now` создаёт файл, `restore` его восстанавливает. Добавь это как отдельную задачу в CI (без cloudflared).

8. **Документация**: дополни `docs/LAUNCH-PC.md` реальными командами и именами файлов (каркас уже есть — не меняй порядок шагов, только уточняй). Обнови `CLAUDE.md` (команды продакшна, импорт, настройка `auth.deviceCode.enabled`).

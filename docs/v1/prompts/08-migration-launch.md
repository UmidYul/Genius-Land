# Этап 8 — Перенос данных и запуск

## Промт

Продолжаем платформу Genius Land. Прочитай `CLAUDE.md`, `PRODUCT.md`, `docs/v1/PLAN.md` (§2.2, §6, §7), `Legacy Website Audit/I_new_system_spec.md` (§7 Миграция данных — только как справочник) и общие правила в `docs/v1/prompts/README.md` — следуй им.

Задача: перенести реальные данные из выгрузок старой системы, подготовить продакшн-развёртывание и провести приёмку v1.

Работай в ветке `feature/v1-08-migration-launch`.

**Перед началом спроси Umid**:
- предоставлены ли файлы выгрузки старой системы (ученики, родители, учителя, классы, расписание) и где они;
- хостинг (Q11) и домен;
- какие данные переносим (например, только текущий учебный год, без старых оценок?).
Любые правила очистки, взятые из legacy-аудита (номера-заглушки родителей, дубли и т.п.), — сначала подтвердить у Umid.

Сделай:
1. **Импортёр выгрузок** старой системы (CLI-скрипт в `packages/db`): сопоставление колонок старых файлов с моделью, очистка (дубли, неверные телефоны), распределение по двум филиалам, сопоставление классов 8–11 с группами по направлениям (как распределять — спросить), отчёт о проблемных строках. Режим «пробный прогон» без записи.
2. **Сверка** после импорта: количество учеников, родителей, учителей, классов и групп по каждому филиалу — отчёт для Umid.
3. **Продакшн**: Docker Compose (web, worker, postgres, nginx с HTTPS), переменные окружения, миграции при деплое, health-check, логи с маскированием персональных данных.
4. **Резервные копии**: ежедневный pg_dump, хранение 30 дней, копия вне сервера, инструкция и проверка восстановления.
5. **Мониторинг**: ошибки web и worker, сбои доставки SMS и бота, низкий баланс SMS — уведомление суперадмину в бот.
6. **Приёмка**: пройти критерии из `docs/v1/PLAN.md` §7, результат — чек-лист в PR. E2E-прогон ключевых потоков на копии реальных данных.
7. **Документация**: `docs/OPERATIONS.md` (деплой, бэкапы, восстановление, обновление), краткие инструкции для ролей (учитель, администратор, бухгалтер, директор) на uz и ru — `docs/guides/`.

Открой PR в `main`.

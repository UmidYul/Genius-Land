# Этап 6 — Уведомления и Telegram-бот

## Промт

Продолжаем платформу Genius Land. Прочитай `CLAUDE.md`, `PRODUCT.md` (разделы Notifications и Users), `docs/v1/PLAN.md` (§3.8) и общие правила в `docs/v1/prompts/README.md` — следуй им.

Задача: настоящие каналы доставки и Telegram-бот для родителей, учеников и сотрудников. Бот — **основной** канал. SMS — **редко**: коды и оплата. Родители и ученики не имеют веб-страниц, бот для них — главная точка контакта до выхода приложения.

Работай в ветке `feature/v1-06-notifications-bot`.

**Перед началом спроси Umid** про SMS-провайдера (Q10; в старой системе был Eskiz — это из legacy, нужно подтверждение). До ответа сделай адаптер и оставь провайдер-заглушку.

Сделай:
1. **Каналы**: Telegram (`grammY` в `apps/worker`), SMS (адаптер `SmsProvider`), e-mail (адаптер `EmailProvider`, SMTP). Заглушки из этапа 1 остаются для разработки и тестов.
2. **Привязка Telegram**:
   - пользователь открывает бота и нажимает «Поделиться номером» — бот сверяет номер Telegram-контакта с телефоном в базе и привязывает чат (номер должен принадлежать самому пользователю Telegram);
   - запасной путь: одноразовая ссылка-приглашение (deep link), которую сотрудник может отправить из карточки родителя/ученика;
   - отвязка и смена номера; один телефон — один пользователь.
3. **Маршрутизация** по таблице PLAN §3.8 — правила как данные (`NotificationRule`), редактируемые суперадмином:
   - коды входа и сброса — **всегда во все подключённые каналы, включая SMS**;
   - напоминания об оплате и долг — бот + SMS + e-mail;
   - остальное — только бот; если бота нет, неважные события не отправляются в SMS.
4. **Шаблоны** на uz/ru для каждого события и канала; язык — из настроек пользователя. Для SMS — короткие тексты, учитывать длину (кириллица и латиница считаются по-разному).
5. **Очередь доставки** (pg-boss): повторные попытки, статусы доставки, тихие часы для неважных сообщений (настройка, коды и срочное — без тихих часов), дедупликация.
6. **Подписка на доменные события этапов 3–5**:
   - изменение расписания на сегодня/завтра → бот затронутым ученикам, родителям, учителям;
   - пропуск/опоздание → бот родителям;
   - новые оценки → дайджест в бот (раз в день вечером, время — настройка);
   - счёт выставлен, платёж принят → бот + e-mail;
   - открыт раунд отзывов учителей (этап 2b) → бот учителям; напоминание тем, кто ещё не закончил, за 2 дня до конца раунда (только бот, без SMS);
   - напоминание о сроке оплаты и просрочка → бот + SMS + e-mail.
7. **Бот — функции**:
   - «Сегодня» и «Завтра» — расписание **только на эти два дня**, всегда через `getScheduleForDate` в момент запроса (без кеша). С пометками замен и отмен. Если день нерабочий — так и написать.
   - Родитель с несколькими детьми — выбор ребёнка.
   - Учитель — своё расписание на сегодня/завтра.
   - Баланс и ближайший платёж для родителя (только просмотр).
   - Язык uz/ru.
   - Бот никогда не показывает данные чужих детей (проверка через `can` и область `CHILDREN`/`SELF`).
8. **Рассылки из кабинета**: директор/администратор — по филиалу, классу, группе; классный руководитель — своему классу; бухгалтер — напоминание должникам. Предпросмотр получателей и канала, подтверждение, отчёт о доставке. SMS в рассылке — только для типов «оплата» и «срочно» и с явным подтверждением стоимости.
9. **Журнал отправок** и баланс SMS (если провайдер даёт API) на экране суперадмина.

Тесты: привязка по номеру (чужой номер — отказ); маршрутизация (код уходит во все каналы, оценка — только в бот); расписание в боте отражает изменение, сделанное только что; родитель видит только своих детей; тихие часы; повторные попытки.

Открой PR в `main`.
